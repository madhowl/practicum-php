Работа 6. ООП: каталог на классах

До этой работы весь каталог был написан в процедурном стиле: данные лежали в массивах, а действия — в отдельных функциях (add_product, find_product, validate_product). Теперь мы перепишем ту же логику на объекты. Конспект подробный: каждое новое слово объясняется простыми словами и сразу показывается в коде. Знаний ООП заранее не предполагается.

Как устроен конспект Материал разбит на три части:
  • Часть I. Основы (разделы 1–5): класс, объект, свойства, конструктор, инкапсуляция;
  • Часть II. Поведение и типы (разделы 6–11): статические члены, перечисления, интерфейсы, наследование, исключения, магические методы;
  • Часть III. Организация кода (разделы 12–13): пространства имён, Composer, сборка проекта вместе.

Часть I. Основы

1. Зачем нужно ООП

1.1. Как выглядит процедурный код и что в нём не так

Начнём с задачи: посчитать цену товара со скидкой. В процедурном стиле это выглядит так:

function price_with_discount(int $price, int $discount): float
{
    return round($price * (100 - $discount) / 100, 2);
}

$product = ['title' => 'Ноутбук', 'price' => 54990, 'discount' => 10];
echo price_with_discount($product['price'], $product['discount']);

Пока товар один и программа маленькая, всё хорошо. Но приложение растёт: появляются добавление товара, поиск, сортировка, сохранение в файл, валидация формы. И тут начинаются проблемы:

  1. Массив — «мешок без правил». Функция ожидает два числа, но никто не мешает вызвать price_with_discount('дорого', []) — программа упадёт во время работы, а не при написании кода.
  2. Структура не проверяется. Если в одном месте товар описан ключом 'cost', а в другом 'price', PHP не подскажет ошибку — просто получится пустое значение.
  3. Данные и логика врозь. Цена, скидка и правило расчёта — это одно понятие «товар», но живут они в разных местах: массив с данными отдельно, функция отдельно.
  4. Всё связано со всем. Изменение структуры товара затрагивает десяток файлов.

Ключевой недостаток: программа не знает про предметную область ничего, кроме «это массив с какими-то ключами».

1.2. Та же задача через объект

$product = new Product(1, 'Ноутбук', Category::Tech, 54990.0, 12, 10);
echo $product->priceWithDiscount();

Здесь товар — единое целое: в нём и данные (название, цена, скидка), и действия над ними. Типы проверяются при создании. Читается как обычный язык: «у товара узнай цену со скидкой».

1.3. Аналогия «чертёж и изделие»

Класс — это чертёж. В чертеже описано, из чего состоит изделие и что оно умеет, но самого изделия ещё нет. Объект — конкретное изделие, сделанное по чертежу.

  • по чертежу «Дом» строят много разных домов (разной площади, цвета);
  • по классу Product создают много разных товаров (разные названия, цены);
  • чертёж один; изделий — сколько угодно, и у каждого свои значения.

Ещё одна аналогия: класс — форма для печенья, объект — само печенье. Форма задаёт, какой будет фигура; каждое печенье при этом отдельное.

1.4. Три кита ООП

  • Инкапсуляция — объект прячет свои данные и сам следит, чтобы они оставались верными;
  • Наследование — один класс может взять поведение другого и дополнить его;
  • Полиморфизм — разные классы можно использовать через общий «договор» (интерфейс), и код не будет знать, какой именно класс ему достался.

1.5. Когда ООП помогает, а когда нет

ООП — не самоцель. Небольшой скрипт из десяти строк выиграет от процедурного стиля. ООП стоит применять, когда:

  • у одного понятия есть и данные, и правила (товар, заказ, корзина);
  • понятий много и их нужно описывать как типы;
  • важен повторяемый «договор» между частями программы;
  • проект будет расти, и хочется менять одну часть, не ломая другие.

1.6. Итог раздела

  • массив не описывает тип: сколько полей, какие ключи, какие типы;
  • класс описывает и данные, и поведение, и правила;
  • объект — конкретный экземпляр класса со своими значениями;
  • ООП помогает, когда понятий много и между ними нужно чёткое разделение.

2. Класс и объект

2.1. Объявление класса

Класс объявляется словом class, имя принято писать с большой буквы. Внутри класса живут свойства (переменные) и методы (функции) — вместе их называют членами класса.

class Product
{
    // свойства: у каждого объекта свои значения
    public int $id;
    public string $title;
    public float $price;

    // метод: действие над объектом
    public function priceWithDiscount(): float
    {
        return $this->price;
    }
}
  • public — модификатор доступа: «видно снаружи» (раздел 5);
  • int $id — типизированное свойство: только целое число;
  • function priceWithDiscount(): float — метод, возвращающий дробное число;
  • $this — ссылка на тот самый объект, у которого вызван метод.

2.2. Что такое «состояние» и «поведение»

  • состояние — значения свойств: id = 1, title = 'Ноутбук', price = 54990;
  • поведение — методы: priceWithDiscount, stockLabel.

В хорошем классе данные и поведение связаны: поведение работает именно с состоянием этого объекта.

2.3. Создание объекта: слово new

$product = new Product();   // создали объект
$product->id = 1;           // записали свойство
$product->title = 'Ноутбук';
$product->price = 54990.0;

echo $product->title;               // Ноутбук
echo $product->priceWithDiscount(); // 54990.0

2.4. Обращение к методам и свойствам: оператор ->

$product->title;                 // свойство
$product->priceWithDiscount();   // метод (со скобками)

Скобки обязательны: без них PHP решит, что вы обращаетесь к свойству. Внутри класса к своим членам обращаются через $this->.

2.5. Несколько объектов независимы

$notebook = new Product();
$notebook->title = 'Ноутбук';

$mouse = new Product();
$mouse->title = 'Мышь';

echo $notebook->title; // Ноутбук — не изменилось
echo $mouse->title;    // Мышь

Объекты не делят состояние между собой. Если нужно общее значение для всех — это делается через static (раздел 6).

2.6. Что печатает var_dump для объекта

var_dump($notebook);
// object(Product)#1 (3) {
//   ["id"]=> int(1)
//   ["title"]=> string(14) "Ноутбук"
//   ["price"]=> float(54990)
// }

print_r и var_export тоже умеют показывать объекты — удобно при отладке.

2.7. instanceof — проверка класса

if ($product instanceof Product) {
    echo 'Это товар';
}

instanceof проверяет не только сам класс, но и его родителей, и реализованные интерфейсы.

2.8. Сравнение объектов: == и ===

$a = new Product();
$a->id = 1;
$a->title = 'Ноутбук';

$b = new Product();
$b->id = 1;
$b->title = 'Ноутбук';

$a == $b;    // true  — объекты «похожи»: те же класс и значения свойств
$a === $b;   // false — это РАЗНЫЕ объекты в памяти

== сравнивает значения свойств, === — идентичность. Два объекта из двух new — всегда разные.

2.9. Объекты передаются «по ссылке»

function rename(Product $product): void
{
    $product->title = 'Переименовано';
}

$notebook = new Product();
rename($notebook);
echo $notebook->title;   // Переименовано

Это удобно, но требует аккуратности. Именно поэтому часто делают объекты неизменяемыми (readonly, раздел 5).

2.10. Типичные ошибки новичка

  • забыли new: $p = Product(); — нельзя, нужно $p = new Product();;
  • поставили $ у имени свойства после ->: правильно $p->title, а не $p->$title;
  • забыли скобки у метода: $p->priceWithDiscount;
  • используют $this вне метода — снаружи класса его нет;
  • надеются, что == и === для объектов означают одно и то же.

2.11. Итог раздела

  • класс — описание, объект — конкретный экземпляр;
  • new создаёт объект, -> обращается к его членам, $this — «этот объект»;
  • объекты независимы, сравниваются по == и ===, передаются по ссылке.

3. Свойства: типы и значения по умолчанию

3.1. Зачем указывать тип

class Product
{
    public int $id;                  // только целое
    public string $title = '';       // строка, по умолчанию пустая
    public float $price = 0.0;       // дробное
    public int $stock = 0;           // целое, 0 — допустимо
    public bool $available = false;  // логическое
}
$p = new Product();
$p->id = 'один';   // TypeError: cannot assign string to property of type int

3.2. Значения по умолчанию

Свойство может иметь начальное значение. Если его нет, свойство при создании объекта считается неинициализированным:

class Product
{
    public int $id;   // без значения по умолчанию
}

$p = new Product();
echo $p->id;          // Error: must not be accessed before initialization

3.3. Nullable-типы: ?Type

public ?string $description = null;   // строка ИЛИ null
public ?Category $category = null;

3.4. Объединённые (union) типы

public int|string $code;      // либо число, либо строка
public int|float $amount = 0; // целое или дробное

3.5. Специальные типы mixed и void

  • mixed — «любое значение» (используйте редко, он теряет проверку типов);
  • void — «метод ничего не возвращает» (для возвращаемого типа).
public function dump(mixed $value): void
{
    var_dump($value);   // ничего не возвращаем
}

3.6. Статические свойства (кратко)

class Counter
{
    public static int $created = 0;

    public function __construct()
    {
        self::$created++;   // общий счётчик для всех объектов
    }
}

new Counter();
new Counter();
echo Counter::$created;     // 2

3.7. Типичные ошибки новичка

  • путают объявление свойства (public int $id;) с обычной переменной;
  • записывают строку в int-свойство и удивляются ошибке типа;
  • забывают про неинициализированное свойство;
  • вместо ?Type пытаются «разрешить null» как-то иначе.

3.8. Итог раздела

  • у свойства есть тип и, возможно, значение по умолчанию;
  • ?Type разрешает null, A|B — несколько типов, mixed — любой, void — «ничего не вернуть»;
  • типы ловят ошибки на раннем этапе.

4. Конструктор

4.1. Проблема постепенного заполнения

$product = new Product();
$product->id = 1;
$product->title = 'Ноутбук';
// забыли price — и объект уже нельзя считать полноценным

Конструктор решает эту проблему: это метод __construct, который PHP вызывает автоматически в момент new.

4.2. Обычный конструктор

class Product
{
    public int $id;
    public string $title;
    public float $price;

    public function __construct(int $id, string $title, float $price)
    {
        $this->id = $id;
        $this->title = $title;
        $this->price = $price;
    }
}

$product = new Product(1, 'Ноутбук', 54990.0);

4.3. Сокращённая запись: property promotion

class Product
{
    public function __construct(
        public int $id,
        public string $title,
        public float $price,
    ) {
    }
}

Этот код эквивалентен «длинной» записи. Такой приём называется property promotion. «Под капотом» PHP сам объявляет свойство и присваивает ему значение.

4.4. Значения по умолчанию в конструкторе

class Product
{
    public function __construct(
        public int $id,
        public string $title,
        public float $price = 0.0,
        public int $discount = 0,
    ) {
    }
}

new Product(1, 'Ноутбук');              // discount = 0
new Product(2, 'Мышь', 1990.0, 10);     // discount = 10

Необязательные параметры должны идти после обязательных.

4.5. Именованные аргументы

$product = new Product(
    id: 3,
    title: 'Наушники',
    price: 3990.0,
    discount: 20,
);

4.6. Проверки в конструкторе (инварианты)

final class Product
{
    public function __construct(
        public readonly int $id,
        public readonly string $title,
        public readonly float $price,
    ) {
        if ($price < 0) {
            throw new InvalidArgumentException('Цена не может быть отрицательной');
        }
    }
}

new Product(1, 'Ноутбук', -5);   // исключение — товар не создан

Такие правила называют инвариантами: условия, при которых объект имеет право существовать.

4.7. new как выражение

$labels = array_map(
    fn (Product $product): string => $product->title,
    [new Product(1, 'A', 1.0), new Product(2, 'B', 2.0)]
);

4.8. Типичные ошибки новичка

  • вызвать конструктор как обычный метод ($p->__construct(...)) — не нужно;
  • забыть передать обязательный аргумент;
  • при promotion написать $this->public int $id;
  • поставить необязательный параметр перед обязательным.

4.9. Итог раздела

  • конструктор гарантирует, что объект сразу получает нужные данные;
  • property promotion и именованные аргументы делают код короче;
  • проверки в конструкторе защищают инварианты объекта.

5. Инкапсуляция и readonly

5.1. Что такое инкапсуляция

Инкапсуляция — это когда объект прячет внутренние данные и не даёт сломать себя снаружи. Управляют доступом три слова:

СловоКто видит свойство или метод
publicвсе: и внутри класса, и снаружи
protectedсам класс и его наследники (раздел 9)
privateтолько сам класс, снаружи недоступно

5.2. Почему открытые данные опасны

$product->price = -100;   // бессмысленный товар

Если свойство private, снаружи к нему не подобраться:

$p->price = -100;   // Error: Cannot access private property

5.3. Геттеры: контролируемое чтение

class Product
{
    private float $price;

    public function __construct(float $price)
    {
        if ($price < 0) {
            throw new InvalidArgumentException('Цена не может быть отрицательной');
        }
        $this->price = $price;
    }

    public function price(): float
    {
        return $this->price;
    }
}

$p = new Product(100.0);
echo $p->price();   // 100.0

5.4. Управляемое изменение через методы

public function applyDiscount(float $discount): void
{
    if ($discount < 0 || $discount > 100) {
        throw new InvalidArgumentException('Скидка должна быть от 0 до 100');
    }
    $this->discount = $discount;
}

5.5. readonly: неизменяемые объекты

final class Product
{
    public function __construct(
        public readonly int $id,
        public readonly string $title,
        public readonly float $price,
    ) {
        if ($price < 0) {
            throw new InvalidArgumentException('Цена не может быть отрицательной');
        }
    }
}

$p = new Product(1, 'Ноутбук', 54990.0);
$p->price = 100;   // Error: Cannot modify readonly property

readonly-свойство задаётся ровно один раз — в конструкторе. Такой объект называют неизменяемым. Чтобы «поменять» товар, создают новый объект.

5.6. final — от класса нельзя наследоваться

final class Product { /* ... */ }

// class DiscountedProduct extends Product {}  // Error: cannot extend final class

5.7. Приватный метод-помощник

final class Product
{
    public function __construct(
        public readonly float $price,
        public readonly int $discount,
    ) {
    }

    public function priceWithDiscount(): float
    {
        return $this->apply($this->price, $this->discount);
    }

    private function apply(float $price, int $discount): float
    {
        return round($price * (100 - $discount) / 100, 2);
    }
}

Снаружи apply() не виден: это деталь реализации. Наружу выставлено только необходимое — «узкий интерфейс» класса.

5.8. Типичные ошибки новичка

  • пытаться изменить readonly-свойство после создания объекта;
  • обращаться снаружи к private-свойству;
  • делать все свойства public «чтобы проще»;
  • забывать, что final-класс нельзя наследовать.

5.9. Итог раздела

  • инкапсуляция прячет данные и защищает инварианты;
  • геттеры и методы изменения дают контролируемый доступ;
  • readonly делает объект неизменяемым, final запрещает наследование.

Часть II. Поведение и типы

6. static, константы класса и :: против ->

6.1. Что значит «принадлежит классу»

Обычный метод или свойство принадлежит объекту. Но иногда значение относится ко всему классу. Такие члены называют статическими и помечают словом static.

6.2. Статический метод

class Html
{
    public static function e(string $value): string
    {
        return htmlspecialchars($value, ENT_QUOTES, 'UTF-8');
    }
}

echo Html::e('<b>привет</b>'); // &lt;b&gt;привет&lt;/b&gt;

Внутри статического метода нет $this. К другой статике того же класса обращаются через self::.

6.3. Константы класса

class Config
{
    public const PER_PAGE = 5;

    public static function perPage(): int
    {
        return self::PER_PAGE;
    }
}

echo Config::PER_PAGE;    // 5
echo Config::perPage();   // 5

6.4. Статические свойства

class Counter
{
    public static int $created = 0;

    public function __construct()
    {
        self::$created++;
    }
}

new Counter();
new Counter();
echo Counter::$created;   // 2

Обратите внимание на self::$created: у статических свойств тоже есть знак $.

6.5. Статическая фабрика

final class Product
{
    public function __construct(
        public readonly int $id,
        public readonly string $title,
        public readonly float $price,
    ) {
    }

    // фабрика: собрать товар из массива (например, из JSON)
    public static function fromArray(array $row): self
    {
        return new self(
            id: (int) ($row['id'] ?? 0),
            title: (string) ($row['title'] ?? ''),
            price: (float) ($row['price'] ?? 0),
        );
    }
}

new self(...) означает «создать объект того же класса». Такой метод вызывают Product::fromArray($row).

6.6. Аннотация @return self

/** @return Product[] */
public function all(): array
{
    return $this->products;
}

Аннотация не проверяется PHP, но помогает редактору при автодополнении.

6.7. :: против ->: шпаргалка

ЗаписьК чему обращаемсяПример
$obj->method()метод объекта$product->price()
$obj->propсвойство объекта$product->title
Class::method()статический методHtml::e($x)
Class::CONSTконстанта классаConfig::PER_PAGE
self::method()статика внутри классаself::perPage()
self::$propстатическое свойствоself::$created

6.8. Типичные ошибки новичка

  • $product::priceWithDiscount() — так к обычному методу не обращаются;
  • Html->e(...) — статический метод вызывается через ::;
  • использовать $this в статическом методе;
  • забыть $ у статического свойства: нужно self::$created.

6.9. Итог раздела

  • static — «принадлежит классу, а не объекту»;
  • статические методы и константы вызывают через ::;
  • статические фабрики (fromArray) удобны для создания объектов из данных.

7. Перечисления enum

7.1. Проблема строковых категорий

В процедурном коде категория была строкой: 'Техника'. Строку легко опечатать, и PHP об этом не предупредит. Перечисление (enum) — это тип с заранее известным списком допустимых значений.

7.2. Объявление enum

enum Category: string
{
    case Tech = 'Техника';
    case Games = 'Игры';
    case Accessories = 'Аксессуары';
}
  • каждый вариант — это case;
  • : string означает, что у варианта есть строковое значение (->value);
  • один и тот же вариант — это один и тот же объект.

7.3. Методы внутри enum

enum Category: string
{
    case Tech = 'Техника';
    case Games = 'Игры';
    case Accessories = 'Аксессуары';

    public function label(): string
    {
        return $this->value;          // человекочитаемое название
    }

    public static function labels(): array
    {
        return array_map(
            fn (self $category): string => $category->value,
            self::cases()
        );
    }
}

7.4. Работа со значениями

Category::Tech->value;              // 'Техника'  — строковое значение
Category::Games->label();           // 'Игры'     — метод у варианта
Category::from('Аксессуары');       // Category::Accessories
Category::tryFrom('Ерунда');        // null
Category::cases();                  // все варианты
Category::labels();                 // ['Техника', 'Игры', 'Аксессуары']
  • from() бросает ошибку, если значения нет в списке;
  • tryFrom() в этом случае возвращает null — им удобно проверять данные из формы или файла.

7.5. enum и match

public function shortName(): string
{
    return match ($this) {
        self::Tech => 'Тех',
        self::Games => 'Игры',
        self::Accessories => 'Акс',
    };
}

match без default требует перечислить все варианты — хорошая защита.

7.6. Перебор вариантов

$options = '';
foreach (Category::cases() as $category) {
    $options .= '<option value="' . $category->value . '">'
        . $category->label() . '</option>';
}

7.7. enum как тип

final class Product
{
    public function __construct(
        public readonly string $title,
        public readonly Category $category,   // только Category, не строка
    ) {
    }
}

7.8. Почему это лучше строки

  • опечатка невозможна — компилятор подсказывает варианты;
  • сравнение === надёжно;
  • в match — проверка полноты;
  • редактор подсказывает, какие категории существуют.

7.9. Типичные ошибки новичка

  • сравнить enum со строкой: $category === 'Техника' не сработает — нужно $category === Category::Tech или $category->value === 'Техника';
  • использовать from() на «сырых» данных формы без обработки ошибки — лучше tryFrom() и проверка на null;
  • забыть : string, если нужен ->value.

7.10. Итог раздела

  • enum — строгий список допустимых значений;
  • from()/tryFrom() переводят строку в вариант, ->value и методы — обратно;
  • enum делает категорию типом, а не строкой.

8. Интерфейсы и полиморфизм

8.1. Что такое интерфейс

Интерфейс — это «договор» или «список обязанностей»: методы без реализации, которые класс, подписавший контракт словом implements, обязан написать.

Аналогия. Розетка — это интерфейс: у неё фиксированная форма. Любой прибор с подходящей вилкой можно включить, и розетке не важно, чайник это или зарядка.

8.2. Объявление интерфейса

interface StorageInterface
{
    /** @return array<int, array<string, mixed>> */
    public function load(): array;

    /** @param array<int, array<string, mixed>> $rows */
    public function save(array $rows): void;
}

8.3. Реализация интерфейса

final class JsonFileStorage implements StorageInterface
{
    public function __construct(private readonly string $file)
    {
    }

    public function load(): array
    {
        // ... читает файл, чинит испорченный, возвращает массив
    }

    public function save(array $rows): void
    {
        // ... записывает массив в JSON-файл
    }
}

Класс обязан реализовать все методы интерфейса с совпадающими сигнатурами.

8.4. Что такое полиморфизм

function backup(StorageInterface $storage): void
{
    $rows = $storage->load();   // работает с ЛЮБЫМ хранилищем
    // ...
}

Сегодня мы передадим файловое хранилище, завтра — работающее с базой данных. Функция backup менять не придётся.

8.5. Внедрение зависимости (DI)

$storage = new JsonFileStorage(__DIR__ . '/data/catalog.json');
$repository = new CatalogRepository($storage);   // зависимость передана снаружи

CatalogRepository не создаёт хранилище сам, а принимает готовым. Это гибко: легко заменить хранилище и подсунуть в тестах временный файл.

8.6. Типизация по интерфейсу

public function __construct(private readonly StorageInterface $storage)
{
}

8.7. Интерфейс как замена наследованию

final class Catalog implements Countable, IteratorAggregate
{
    // count() из Countable и getIterator() из IteratorAggregate
}

Класс может реализовать сколько угодно интерфейсов, и это не создаёт сложных цепочек наследования.

8.8. Типичные ошибки новичка

  • забыть реализовать метод из интерфейса → ошибка «must implement»;
  • изменить сигнатуру метода из интерфейса — нельзя;
  • создавать зависимость внутри класса вместо передачи снаружи;
  • путать extends (наследование класса) и implements (интерфейс).

8.9. Итог раздела

  • интерфейс — договор о том, что класс умеет;
  • полиморфизм позволяет писать код, независимый от конкретной реализации;
  • DI — способ передавать зависимости снаружи.

9. Наследование и abstract

9.1. Что такое наследование

Наследование позволяет одному классу взять поведение другого и дополнить его. Пишется словом extends.

Аналогия. «Транспорт» с методом «двигаться». «Автомобиль» и «Велосипед» наследуют его и добавляют свои детали.

9.2. Свой пример: своё исключение

class ProductNotFoundException extends RuntimeException
{
    public function __construct(public readonly int $productId)
    {
        parent::__construct("Товар #{$productId} не найден");
    }
}
  • он получает всё поведение родителя (умеет быть «выброшенным»);
  • добавляет своё — свойство productId;
  • parent::__construct(...) вызывает конструктор родителя.

9.3. Переопределение методов

class Animal
{
    public function sound(): string
    {
        return '...';
    }
}

class Dog extends Animal
{
    public function sound(): string
    {
        return 'Гав';
    }
}

echo (new Dog())->sound();   // Гав

9.4. protected — доступ для наследников

class Animal
{
    protected string $name = '';

    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

class Dog extends Animal
{
    public function greeting(): string
    {
        return 'Привет, я ' . $this->name;   // доступ к protected
    }
}

9.5. Абстрактные классы и методы

abstract class Shape
{
    abstract public function area(): float;   // реализацию пишет наследник

    public function describe(): string
    {
        return 'Площадь: ' . $this->area();
    }
}

class Circle extends Shape
{
    public function __construct(private float $radius)
    {
    }

    public function area(): float
    {
        return round(M_PI * $this->radius ** 2, 2);
    }
}
  • объект abstract-класса создать нельзя;
  • abstract-метод не имеет тела — наследник обязан его реализовать.

9.6. Интерфейс против абстрактного класса

ВопросИнтерфейсАбстрактный класс
Можно реализовать несколько?да (implements A, B)нет (только один extends)
Есть ли общий код?нетда
Есть ли свойства?нетда
Когда использовать?«что умеет»«чем является»

9.7. final — остановить наследование

final class Product { /* ... */ }

final public function id(): int
{
    return $this->id;
}

9.8. Когда наследование не нужно

// Плохо: «репозиторий ЯВЛЯЕТСЯ хранилищем» — сомнительно
class CatalogRepository extends JsonFileStorage {}

// Хорошо: «репозиторий ИСПОЛЬЗУЕТ хранилище»
class CatalogRepository
{
    public function __construct(private StorageInterface $storage) {}
}

9.9. Типичные ошибки новичка

  • забыть parent::__construct();
  • перепутать extends и implements;
  • пытаться создать объект abstract-класса напрямую;
  • наследовать «на всякий случай» вместо композиции.

9.10. Итог раздела

  • наследование расширяет класс, parent:: обращается к родителю;
  • abstract задаёт «заготовку», которую дополняют наследники;
  • final запрещает наследование; композиция часто лучше наследования.

10. Исключения

10.1. Что такое исключение

Исключение — способ сообщить об ошибке, которую нельзя «переварить» на месте. Исключение «бросают» словом throw и «ловят» через try / catch.

try {
    $product = $repository->find(999);   // может бросить исключение
    echo $product->title;
} catch (ProductNotFoundException $e) {
    http_response_code(404);
    echo $e->getMessage();               // «Товар #999 не найден»
}

10.2. throw и объект исключения

if ($product === null) {
    throw new ProductNotFoundException($id);
}

После throw выполнение метода прерывается, и исключение «всплывает» вверх до ближайшего подходящего catch. Если такого нет — фатальная ошибка «Uncaught».

10.3. Иерархия исключений

Throwable
├── Error
│   └── TypeError, ValueError, ...
└── Exception
    ├── RuntimeException
    │   └── ProductNotFoundException
    ├── InvalidArgumentException
    │   └── (наш) InvalidArgumentException
    └── ...

10.4. Своё исключение

class ProductNotFoundException extends RuntimeException
{
    public function __construct(public readonly int $productId)
    {
        parent::__construct("Товар #{$productId} не найден");
    }
}

Своё исключение удобно: говорящее имя, дополнительные данные, можно ловить отдельно.

10.5. Полезные методы исключения

try {
    $repository->find(999);
} catch (ProductNotFoundException $e) {
    echo $e->getMessage();   // текст сообщения
    echo $e->getCode();      // код (int), обычно 0
    echo $e->productId;      // наше дополнительное свойство
}

10.6. Несколько catch и finally

try {
    $repository->find($id);
} catch (ProductNotFoundException $e) {
    http_response_code(404);
} catch (Throwable $e) {
    http_response_code(500);
    echo 'Что-то пошло не так';
}

Блок finally выполняется всегда — и при ошибке, и без неё:

try {
    $storage->save($rows);
} catch (StorageException $e) {
    echo 'Ошибка записи';
} finally {
    echo 'Попытка записи завершена';
}

10.7. Цепочка исключений (previous)

try {
    $json = json_encode($rows);
} catch (Throwable $e) {
    throw new StorageException('Не удалось сериализовать каталог', previous: $e);
}

Позже $e->getPrevious() вернёт исходную ошибку.

10.8. Главное правило: массив или исключение

  • ошибки пользователя (пустое название, цена-текст, скидка 150) — ожидаемая ситуация. Их собирают в массив и показывают под полями формы;
  • «невозможные» ситуации (товара нет, файл не читается) — исключения: программа должна сменить ход выполнения.

Поэтому в проекте:

  • ProductValidator::validate() возвращает массив ошибок;
  • репозиторий бросает ProductNotFoundException;
  • хранилище бросает StorageException;
  • конструктор Product бросает InvalidArgumentException.

10.9. Типичные ошибки новичка

  • обернуть в try весь код «на всякий случай»;
  • «проглотить» исключение пустым catch {};
  • использовать исключения для обычной валидации формы вместо массива;
  • ловить Exception там, где можно поймать точный класс.

10.10. Итог раздела

  • throw бросает исключение, try/catch ловит, finally выполняется всегда;
  • свои исключения делают ошибки говорящими и перехватываемыми точечно;
  • ошибки ввода — массив, «невозможные» ситуации — исключения.

11. Магические методы и встроенные интерфейсы

11.1. Что такое магические методы

Магические методы — методы с именами из двух подчёркиваний. PHP вызывает их сам в особых ситуациях:

  • __construct(...) — при создании объекта;
  • __toString() — когда объект превращают в строку.

11.2. __toString

public function __toString(): string
{
    return sprintf('#%d %s — %s', $this->id, $this->title, $this->category->value);
}
$product = new Product(3, 'Наушники JBL Tune', Category::Accessories, 3990.0, 30, 20);
echo $product;              // #3 Наушники JBL Tune — Аксессуары
echo 'Товар: ' . $product;  // Товар: #3 Наушники JBL Tune — Аксессуары

Без __toString попытка превратить объект в строку — фатальная ошибка.

11.3. Зачем встроенные интерфейсы

Мы хотим, чтобы с объектом Catalog можно было работать как с массивом: считать через count() и перебирать через foreach:

  • Countable — добавляет работу count();
  • IteratorAggregate — добавляет работу foreach.

11.4. Реализация Countable и IteratorAggregate

final class Catalog implements Countable, IteratorAggregate
{
    /** @var Product[] */
    private array $products = [];

    public function count(): int
    {
        return count($this->products);
    }

    public function getIterator(): Traversable
    {
        return new ArrayIterator($this->products);
    }
}

$catalog = new Catalog([$product]);
count($catalog);              // работает благодаря Countable
foreach ($catalog as $item) { // работает благодаря IteratorAggregate
    echo $item->title;
}

Мы «одеваем» объект в привычную для PHP одежду массива, оставляя внутри свою структуру.

11.5. Почему это удобно

foreach ($catalog->all() as $item) { ... }   // так тоже можно
foreach ($catalog as $item) { ... }          // но так короче и естественнее

11.6. Другие магические методы (обзорно)

  • __get/__set — доступ к «виртуальным» свойствам;
  • __isset/__unset — работа isset()/unset();
  • __call — вызов несуществующего метода;
  • __invoke — вызов объекта как функции;
  • __clone — настройка копирования.

11.7. Типичные ошибки новичка

  • надеяться, что echo $object заработает без __toString;
  • реализовать Countable, но забыть count();
  • возвращать из getIterator() массив вместо объекта-итератора — нужен ArrayIterator.

11.8. Итог раздела

  • магические методы PHP вызывает сам; __toString печатает объект;
  • встроенные интерфейсы Countable/IteratorAggregate включают count() и foreach для объекта.

Часть III. Организация кода

12. Пространства имён и автозагрузка через Composer

12.1. Проблема: имена классов могут совпасть

Когда классов много, их короткие имена могут совпасть. Решение — пространства имён (namespace): это «фамилии» для классов.

namespace App;      // все классы ниже принадлежат пространству App

final class Product { /* ... */ }

Полное имя класса теперь — App\Product.

12.2. Импорт через use

use App\Product;
use App\CatalogRepository;

$product = new Product(...);        // PHP понимает: App\Product
$repo = new CatalogRepository(...); // PHP понимает: App\CatalogRepository

Можно давать псевдоним: use App\Product as ProductEntity;.

12.3. Проблема: подключать файлы вручную

require 'src/Category.php';
require 'src/Product.php';
require 'src/ProductValidator.php';
// ... и ещё десять строк

Это неудобно и легко забыть строку. Решение — автозагрузка: PHP сам подключает файл, когда встречает неизвестный класс.

12.4. Composer: автозагрузка по правилу PSR-4

В современном PHP автозагрузку почти всегда доверяют Composer. Достаточно описать правило «где искать классы» в файле composer.json:

{
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}

Читается так: «классы, чьё имя начинается с App\, лежат в папке src/». Правило соответствия имени класса и пути к файлу называют PSR-4:

КлассФайл
App\Productsrc/Product.php
App\Catalogsrc/Catalog.php
App\Categorysrc/Category.php

Имя файла совпадает с именем класса — это обязательное правило PSR-4.

12.5. Установка: composer install

composer install

Composer создаёт папку vendor/ и генерирует файл vendor/autoload.php — готовый автозагрузчик. Его подключают один раз:

require __DIR__ . '/vendor/autoload.php';

// дальше можно смело писать:
$product = new App\Product(...);

12.6. Что такое vendor/

vendor/ — папка со сторонними библиотеками и сгенерированным автозагрузчиком. Правило: её не редактируют руками и не коммитят в репозиторий. Она полностью воспроизводится командой composer install. Поэтому vendor/ добавляют в .gitignore.

12.7. Автозагрузка после добавления классов

При PSR-4-автозагрузке новые классы подхватываются автоматически. Если же меняется само правило (например, добавили пространство App\Admin\ → src/Admin/), нужно перегенерировать автозагрузчик:

composer dump-autoload

12.8. Что Composer делает «под капотом»

Composer не волшебник: сгенерированный им vendor/autoload.php внутри использует тот самый механизм spl_autoload_register. Просто писать его руками больше не нужно.

12.9. Мини-версия «как это выглядело бы руками»

spl_autoload_register(function (string $class): void {
    $prefix = 'App\\';
    if (!str_starts_with($class, $prefix)) {
        return;
    }
    $relative = substr($class, strlen($prefix));         // Product, Catalog, ...
    $file = __DIR__ . '/src/' . str_replace('\\', '/', $relative) . '.php';
    if (is_file($file)) {
        require $file;
    }
});

Именно это (в более развитом виде) Composer и генерирует. В задании мы этот код писать не будем — используем готовый vendor/autoload.php.

12.10. Типичные ошибки новичка

  • забыли выполнить composer install — тогда нет vendor/autoload.php;
  • файл назван не так, как класс (product.php вместо Product.php) — PSR-4 не найдёт;
  • класс объявлен не в том namespace, что указан в composer.json;
  • вручную правят файлы в vendor/ — при следующем composer install изменения пропадут.

12.11. Итог раздела

  • пространство имён делает имена классов уникальными, use сокращает запись;
  • Composer по правилу PSR-4 генерирует автозагрузчик vendor/autoload.php;
  • composer install создаёт vendor/, новые классы в src/ подхватываются сами;
  • vendor/ не коммитят; правило задаётся в composer.json.

13.2. Схема связей

Сплошная стрелка — «использует», пунктирная — «реализует» (implements):

flowchart TD
    Pages["страницы
index / add / edit / delete"]
    Repo["CatalogRepository"]
    Storage["StorageInterface"]
    Json["JsonFileStorage"]
    Catalog["Catalog"]
    Product["Product"]
    Category["Category"]
    Html["Html"]

    Pages --> Repo
    Repo --> Storage
    Repo --> Catalog
    Json -.->|implements| Storage
    Catalog --> Product
    Product --> Category
    Pages --> Html
  • страницы ничего не знают о файле — только о репозитории;
  • репозиторий ничего не знает о конкретном хранилище — только об интерфейсе;
  • Catalog работает только с объектами Product;
  • Product знает про Category и умеет считать цену.

Такое разделение называют слоями.

13.3. Путь одного запроса

  1. index.php подключает vendor/autoload.php и создаёт объекты;
  2. вызывает $repository->load() — «дай каталог»;
  3. репозиторий просит строки у $storage->load();
  4. JsonFileStorage читает data/catalog.json, при необходимости чинит его;
  5. репозиторий превращает строки в объекты Product и собирает Catalog;
  6. index.php вызывает search(), filterByCategory(), sortByPrice(), paginate();
  7. страница выводит товары, экранируя всё через Html::e().

13.5. Почему такая архитектура хороша

  • Понятность. Каждый класс делает одно и понимает только своё.
  • Заменяемость. Хранилище за интерфейсом: файл сегодня, база завтра.
  • Тестируемость. Product и Catalog — чистые объекты, их можно проверять без браузера.
  • Безопасность. Вывод только через Html::e(), вход только через валидатор, инварианты — в конструкторе.
