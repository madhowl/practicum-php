Работа 4. Файлы и JSON

Конспект: чтение и запись файлов, JSON как формат хранения, обработка ошибок.

Зачем JSON

Каталог раньше жил в PHP-файле — менять его мог только программист. Хранение в JSON-файле даёт два бонуса:

  • данные отделены от кода — их можно редактировать руками или программой;
  • сайт сам себя обновляет — форму добавления из работы 3 теперь можно «подружить» с файлом.

Чтение и запись файлов

// весь файл одной строкой
$json = file_get_contents('data/catalog.json');   // string|false
$ok   = file_put_contents('data/catalog.json', $json, LOCK_EX);  // int|false

// построчно (для больших файлов или построчной обработки)
$fp = fopen('data/catalog.json', 'r');            // 'r' — чтение
if ($fp === false) { /* не открылся */ }
while (($line = fgets($fp)) !== false) {
    // обработать строку
}
fclose($fp);

Проверки перед чтением:

is_file($file);        // существует ли файл
is_readable($file);    // читается ли
is_writable($file);    // записывается ли
filesize($file);       // размер в байтах
filemtime($file);      // время изменения (timestamp) — для вывода «изменён: …»

json_encode / json_decode

$array = [['title' => 'Ноутбук', 'price' => 54990]];

$json = json_encode($array, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
// JSON_PRETTY_PRINT      — «красивый» многострочный вид
// JSON_UNESCAPED_UNICODE — не превращать «Ноутбук» в \u041d\u043e...

$back = json_decode($json, true);   // true = вернуть массив, а не объект
// json_decode(..., false) вернёт stdClass-объекты — с ними неудобно
Проверяйте результат json_encode возвращает false, если данные не сериализуются (например, теряются при конвертации типов).

json_validate (PHP 8.3)

Сначала просто проверить, что строка — корректный JSON, и только потом разбирать:

if (json_validate($json)) {
    $catalog = json_decode($json, true);
} else {
    // файл испорчен — восстанавливаем
}

Блокировка при записи: LOCK_EX

Два посетителя могут сохранить каталог почти одновременно — файл «затрётся». Флаг LOCK_EX ставит эксклюзивную блокировку на время записи:

file_put_contents($file, $json, LOCK_EX);

«Выживать» при любом состоянии файла

Правило надёжной модели: функция всегда возвращает массив, что бы ни было с файлом. Цепочка проверок:

  1. файла нет / не читается → создать с каталогом по умолчанию;
  2. file_get_contents вернул false → восстановить;
  3. json_validate не прошёл → восстановить;
  4. json_decode вернул не список → восстановить (JSON-объект {...} декодируется в ассоциативный массив — спасает array_is_list());
  5. всё хорошо → вернуть данные.

Восстановление: испорченный файл не стираем молча, а переименовываем с датой:

@rename($file, $file . '.broken.' . date('YmdHis'));

Функции-«пути»

__DIR__;  // абсолютный путь к папке текущего файла
dirname(__FILE__); // та же идея для старых версий
// Использование __DIR__ делает пути независимыми от рабочей папки запуска.

PRG-паттерн (в коде index.php)

Без него нажатие F5 после успешного POST повторно добавит товар. Решаем так: после сохранения — редирект на GET-страницу, сообщение передаём через параметр ?added=1:

header('Location: index.php?added=1');
exit;
