Работа 3. Строки и формы

Конспект: работа со строками, GET/POST, валидация и безопасный вывод.

Строковые функции, которые пригодятся

trim('  текст  ');           // убрать пробелы по краям
mb_strlen('текст');          // длина в символах (strlen — в байтах!)
mb_strtolower('ТЕКСТ');      // в нижний регистр (русский язык — только mb_*)
str_contains('наушники', 'науш');  // true — подстрока найдена (PHP 8+)
str_starts_with('телефон', 'тел'); // true (PHP 8+)
str_replace('а', 'о', 'каталог');  // католог (все вхождения)
explode(', ', 'a, b');       // ['a', 'b'] — строка в массив
implode('; ', ['a','b']);    // 'a; b' — массив в строку
substr('привет', 0, 3);      // 'при' — срез по позициям
Почему mb_* Обычные strlen/strtolower работают с байтами. Кириллическая буква — 2 байта, поэтому strlen('кот') вернёт 6, а mb_strlen — 3. Для русского текста почти всегда нужны mb_*.

Регулярные выражения (самое начало)

// preg_match: вернёт 1, если шаблон найден, 0 — если нет
$phone = '+7 900 123 45 67';
if (preg_match('/^\+7[\s\-]?\d{3}[\s\-]?\d{3}[\s\-]?\d{2}[\s\-]?\d{2}$/', $phone)) {
    echo 'Телефон валиден.';
}
  • /.../ — границы шаблона;
  • ^ — начало строки, $ — конец;
  • \d — цифра, {3} — ровно три раза, [\s\-]? — пробел/дефис, необязательно.

Регулярки мощные, но для простых проверок (название не пустое, цена — число) хватает обычных функций и is_numeric().

Суперглобальные массивы

PHP автоматически подставляет данные из запроса:

$_GET   // параметры из адресной строки (?search=...&category=...)
$_POST  // данные, посланные формой method="post"
$_SERVER['REQUEST_METHOD']  // 'GET' или 'POST'

Как отличить отправку формы:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // данные пришли из формы
}

Форма поиска шлёт данные методом GET — ссылкой можно поделиться, кнопка «Назад» работает, на редиректе ничего не теряется. Форма изменения данных (добавление товара) — методом POST.

Валидация = доверять нельзя

Входные данные — строки, причём какие угодно. Правило: сначала проверь, потом используй.

$errors = [];                       // список ошибок
if (trim($data['title'] ?? '') === '') {
    $errors['title'] = 'Укажите название.';
} elseif (mb_strlen(trim($data['title'])) < 3) {
    $errors['title'] = 'Название слишком короткое.';
}
if (!is_numeric($data['price'] ?? '')) {
    $errors['price'] = 'Цена должна быть числом.';
} elseif ((float) $data['price'] <= 0) {
    $errors['price'] = 'Цена должна быть больше нуля.';
}
// $errors === [] => всё хорошо

?? (null-скипающий оператор): $_POST['title'] ?? '' — вернёт '', если ключа нет, и не ругнётся «Undefined array key».

Приведение типов часто обязательно

Из формы всё приходит строками. Перед сохранением превращаем в нужные типы:

$data = [
    'title'    => trim((string) $data['title']),      // строка
    'price'    => (float) $data['price'],             // число с дробной частью
    'stock'    => (int) $data['stock'],               // целое
    'discount' => (int) $data['discount'],
];

Безопасный вывод: XSS

Пользователь может передать <script>alert(1)</script> в поле названия. Если вывести это как есть — браузер выполнит скрипт (XSS-атака). Решение — эскейпить при выводе:

echo htmlspecialchars($value, ENT_QUOTES, 'UTF-8');

Удобно обернуть в короткую функцию e() и использовать её для всего, что выводится в HTML. Для значения внутри value="..." атрибута тоже — поэтому ENT_QUOTES.

Важно Эскейпим при выводе, а не при вводе. Данные храним «как есть», а обязательно «чистим» в момент печати.

PRG (не в этой работе, но пригодится в 5-й)

Если после POST нажать F5 — браузер повторит отправку формы (продублирует товар). Лечится «PRG»: после успешного POST делаем header('Location: index.php') с редиректом на GET. Это понадобится в работе 5.
