Работа 5. Каталог товаров — финальный CRUD

Цель

Собрать приложение с четырьмя CRUD-операциями: список с поиском и фильтрами, добавление, редактирование и удаление (с подтверждением). Данные — в data/catalog.json, всё через процедурные функции без ООП.

Задание

Постройте на основе работ 3–4 полное приложение:

  1. Модель (functions.php):
    • load_catalog(), save_catalog(), default_catalog(), next_id() — из работы 4;
    • find_product(array $catalog, int $id): ?array;
    • add_product(array $catalog, array $data): array — добавляет товар и возвращает новый каталог;
    • update_product(array $catalog, int $id, array $data): ?array — правит существующий товар (или null, если такого нет);
    • delete_product(array $catalog, int $id): ?array — убирает товар (или null);
    • функции работы 2 (поиск, фильтры, сортировки, пагинация) и работы 3 (валидация, e()).
  2. Список (index.php): поиск ?search=, фильтр ?category=, сортировка ?sort= (белый список: price_asc, price_desc, title, stock), пагинация по 5 товаров со ссылками, сохраняющими все GET-параметры. Для каждого товара — ссылки «Изменить» и «Удалить». Под таблицей — счётчик товаров и стоимость склада.
  3. Добавление (add.php): форма из работы 3, но теперь реально сохраняет. После успеха — header('Location: index.php?added=N'), сообщение «Товар добавлен» показывается на списке.
  4. Редактирование (edit.php?id=N): те же поля, форма предзаполнена значениями товара. Если товара нет — http_response_code(404) и текст «Товар не найден». После сохранения — редирект Location: index.php?updated=N с сообщением.
  5. Удаление (delete.php?id=N):
    • GET — страница «Удалить товар?» с карточкой товара и кнопкой подтверждения;
    • кнопка — POST-форма на тот же delete.php; удаление выполняется только на POST;
    • после удаления — редирект index.php?deleted=N;
    • для несуществующего id — 404.
  6. Общая вёрстка (layout.php): шапка + общие заголовки — layout_start($title)/layout_finish(). Баннер-заглушка banner(?string $text) — выводит сообщение только если текст задан.

Пометки

  • Вывод — только через e(); значения в полях форм — тоже.
  • Валидация общая для add и edit: validate_product(), при ошибке — подсветить поля и восстановить ввод.
  • id брать так: $id = (int) ($_GET['id'] ?? 0);
  • Пустой каталог — валидное состояние, показывать «Ничего не найдено».

Запуск

php test.php                    # автотесты
php -S localhost:8000 -t pr5    # браузер: http://localhost:8000/index.php

Критерии приёмки

  • php test.php завершается с «ошибок: 0»;
  • добавление → товар в файле и списке, на F5 дублей нет;
  • редактирование → изменения в файле и списке, есть сообщение «обновлён»;
  • удаление → товар пропал в файле и списке, есть сообщение «удалён»;
  • edit.php?id=999 и delete.php?id=999 дают HTML с 404;
  • сортировка меняет порядок, пагинация переживает сочетание search + category + sort;
  • пустой результат поиска показывает «Ничего не найдено», а не ошибку.

Эталонный режим

Полное эталонное решение лежит в solution/ — сравните свою реализацию, только сначала пройдите задание сами.
