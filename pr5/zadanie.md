# Работа 5. Каталог товаров — финальный CRUD

## Цель

Собрать всё, что изучено в работах 1–4, в одно приложение: вывод каталога,
добавление, редактирование и удаление товаров с постоянным хранением
в JSON-файле. Это итог сквозного проекта.

## Задание

1. **`functions.php`** — единый набор функций:
   - модель из работы 4: `load_catalog()`, `save_catalog()`, `catalog_stats()`;
   - CRUD: `find_product()`, `next_id()`, `add_product()`, `update_product()`,
     `delete_product()` (все — чистые функции над массивом);
   - выборку из работы 2: `search_by_name()`, `filter_by_category()`,
     `sort_by_price()`, `sort_by_title()`, `sort_by_stock()`, `paginate()`;
   - валидацию и вывод из работы 3: `validate_product()`, `e()`,
     `price_with_discount()`, `stock_label()`.

2. **`index.php`** — список товаров:
   - поиск, фильтр по категории, сортировка (цена ↑/↓, алфавит, остаток),
     пагинация по 5;
   - ссылки «Изменить» → `edit.php?id=N`, «Удалить» → `delete.php?id=N`;
   - ссылки страниц сохраняют текущие GET-параметры (`query_url()`);
   - сообщения об успехе по `?added=`, `?updated=`, `?deleted=`.

3. **`add.php`** — форма добавления:
   - GET — просто форма;
   - POST — `validate_product()`; при ошибках форма снова с ошибками,
     введённые значения не теряются; при успехе `add_product()`,
     `save_catalog()`, редирект `?added=N`.

4. **`edit.php`** — форма редактирования:
   - сначала `find_product()`; нет товара — `http_response_code(404)`
     и понятный текст;
   - поля формы предзаполнены текущими значениями;
   - POST — валидация, при успехе `update_product()`, `save_catalog()`,
     редирект `?updated=N`.

5. **`delete.php`** — удаление с подтверждением:
   - GET — показать карточку товара и вопрос «Удалить?»;
   - кнопка удаления — POST-форма на тот же файл;
   - на POST — `delete_product()`, `save_catalog()`, редирект `?deleted=N`;
   - нет товара — 404.

6. **`layout.php`** — общие HTML-«обёртки»: `page_header()`, `page_footer()`,
   `banner()` для сообщений об успехе/ошибке.

## Пометки

- Страницы не должны знать, как именно хранится каталог: только
  `load_catalog()` … `save_catalog()`.
- Каждую ЧИСТУЮ функцию тестируйте в `test.php` без браузера: передаёте массив,
  проверяете результат. Файл данных тесты не трогают (дефолтный каталог в памяти).
- Не выводите данные без `e()`; не сохраняйте данные без `validate_product()`.

## Запуск

```bash
php test.php                    # автотесты CRUD-функций
php -S localhost:8000 -t pr5    # приложение: http://localhost:8000/index.php
```

## Критерии приёмки

- [ ] `php test.php` завершается с «ошибок: 0»;
- [ ] в браузере: добавить → товар появился и лежит в `data/catalog.json`;
- [ ] изменить → данные и сообщение «обновлён» видны, id не изменился;
- [ ] удалить → товар исчез, на странице сообщение «удалён»;
- [ ] `edit.php?id=999` возвращает статус 404 и текст «Товар не найден»;
- [ ] поиск + пагинация не «слетают» при переходе по страницам;
- [ ] добавление с ценой-текстом показывает ошибку и не теряет введённое.
