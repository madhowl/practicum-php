# Работа 5. Финальный CRUD

Краткий конспект: что такое CRUD и какие паттерны использованы в итоговом приложении.

## CRUD — четыре базовые операции

Любое приложение с данными в основе имеет четыре действия:

| Буква | Операция     | Наша страница    | HTTP-метод |
|-------|--------------|------------------|------------|
| C     | Create        | `add.php`        | POST       |
| R     | Read (список) | `index.php`      | GET        |
| U     | Update        | `edit.php`       | POST       |
| D     | Delete        | `delete.php`     | POST (подтверждение) |

## Структура приложения

```
pr5/
├── functions.php   — модель (файл+JSON), CRUD, поиск, сортировки, валидация
├── layout.php      — общие HTML-«обёртки» страниц
├── index.php       — список: поиск, фильтры, сортировка, пагинация
├── add.php         — добавление товара
├── edit.php        — редактирование
├── delete.php      — удаление с подтверждением
└── data/catalog.json — хранилище
```

Правило хорошего разделения: **файлы-страницы отвечают за HTTP и HTML,
`functions.php` — за данные**. Чистые функции можно тестировать без браузера.

## Найти товар по id: find_product

```php
function find_product(array $catalog, int $id): ?array
{
    foreach ($catalog as $product) {
        if ((int) $product['id'] === $id) {
            return $product;
        }
    }
    return null;   // не найдено — не ошибка, а показатель «нет такого»
}
```

`?array` означает «вернёт массив или null». Проверка `(int)` важна: из JSON
числа приходят как `int`, но ручная правка файла может дать строки.

## 404 для несуществующего товара

Если `find_product()` вернул `null` — товара нет. Честный ответ сервера:

```php
if ($product === null) {
    http_response_code(404);      // статус для поисковиков и инструментов
    echo '<h1>Товар не найден</h1>';
    exit;
}
```

Код 404 + понятный человеческий текст — то, как должен вести себя сайт,
а не молчаливая белая страница.

## Сортировка «по стрелочкам»

Усложнять страницам не надо: сортировку выбирает пользователь в `index.php`:

```php
$sort = (string) ($_GET['sort'] ?? 'price_asc');
// белый список — только то, что мы сами разрешаем, иначе гадят параметры
$sort = in_array($sort, ['price_asc', 'price_desc', 'title', 'stock'], true)
    ? $sort : 'price_asc';
```

Сортировка через `match` и собранные в работе 2 функции:

```php
$items = match ($sort) {
    'price_desc' => sort_by_price($items, 'desc'),
    'title'      => sort_by_title($items),
    'stock'      => sort_by_stock($items, 'desc'),
    default      => sort_by_price($items, 'asc'),
};
```

## Пагинация не должна терять фильтры

Ссылки на страницы строим из текущих GET-параметров:

```php
function query_url(array $params): string
{
    $all = array_merge($_GET, $params);   // сохраняем search, category, sort
    return 'index.php?' . http_build_query($all);
}
```

`http_build_query` сам экранирует значения — не нужно вручную склеивать `&`.

## PRG: правильный редирект после изменения

После успешного `POST` (add/edit/delete) отвечаем **редиректом**, а не HTML:

```php
$catalog = add_product($catalog, $_POST);
save_catalog($catalog);
header('Location: index.php?added=' . $newId);
exit;
```

Зачем: F5 больше не отправит форму повторно. Сообщение «товар добавлен»
показывается уже на GET-странице по параметру в адресе.

## Удаление с подтверждением

Простая ссылка-удаление опасна: случайный переход погубит данные.
Правильный порядок:

1. `delete.php?id=N` — **GET**: показать карточку товара с просьбойподтвердить;
2. кнопка «Да, удалить» — маленькая **POST-форма** на тот же `delete.php`;
3. только на POST выполняем `delete_product()` + `save_catalog()` + редирект.

## Плюс минус пустой каталог

После удаления всех товаров каталог может стать `[]` — это **валидное состояние**:
`array_is_list([])` даёт `true`, загрузка не «ремонтирует» файл, пагинация с
`perPage = 5` вернёт totalPages = 1. Пустую витрину показываем сообщением
«Ничего не найдено», а не ошибкой.

## Чек-лист безопасности (всё уже в коде)

- вывод в HTML — только через `e()` (`htmlspecialchars`), включая значения полей форм;
- вход — только через `validate_product()`;
- `sort`/`page` — зажаты в безопасные границы;
- id — приводится к `(int)`:
  `$id = (int) ($_GET['id'] ?? 0);` — тут нет места SQL-инъекции, но привычка полезная.
